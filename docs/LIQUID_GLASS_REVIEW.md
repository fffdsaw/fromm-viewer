# Glow ME Liquid Glass 시각 검토

기준: PR #52의 `0222acc`. 기능/일반 웹·설치 앱 배치/PWA/로고·아이콘을 유지하며 CSS와 독창적인 재료 자산을 개선했습니다. 공식 앨범아트나 로고를 새로 복제하지 않았습니다.

## 시안과 비교한 변화

| 영역 | 기존 구현과 목표의 차이 | 최종 적용 |
| --- | --- | --- |
| 헤더 | 거의 균일한 민트 면. 목표의 넓은 물결·굴절 띠 부족 | 독창적인 물/유리 WebP 재료, 아쿠아 베일, 비균일 반사 띠와 밝은 안쪽 테두리. 글자 뒤는 조용하고 밝게 유지 |
| 사이드바 | 한 줄 테두리와 약한 그림자여서 얇아 보임 | 안쪽 밝은 선/반대쪽 청록 음영/3px 안쪽 경계/바닥 반사광을 겹쳐 두께 표현. 메뉴 상단은 뒤쪽 제목이 방해하지 않게 밝은 반사 면 적용 |
| 선택 메뉴·버튼 | 평평한 채움과 대칭적 광택 | 위 왼쪽과 아래 오른쪽의 곡면 반사광, 사선 투과 색상, 밝은 하단 가장자리. 선택 메뉴는 볼록한 캡슐 모양 |
| 검색·달력 | 가독성은 유지할 필요 | 물결 사진을 넣지 않고 옅은 유리 경계만 적용. 입력부/날짜 바탕은 밝고 안정된 면 |
| 대화·영상 | 재질 과장이 감상/읽기를 방해할 수 있음 | 본문은 차분한 밝은 면, 영상의 어두운 표면·재생 컨트롤과 기존 비율 유지 |

1차 헤더가 너무 짙고 복잡해 물결 위의 밝은 베일을 조절했습니다. 웹 메뉴 뒤의 어두운 dimmer가 유리를 회색으로 물들이지 않도록 dimmer를 메뉴 바깥으로 제한했습니다. 이후 상단 여백의 제목 비침도 완화했습니다.

이 구현은 화면 뒤의 픽셀을 실제로 꺾는 광선 추적/실시간 굴절 엔진이 아닙니다. 사진처럼 계산된 정적 광학 재료와 CSS 경계 반사를 합성합니다. 시안과 같은 느낌을 강화하되 글자를 왜곡하거나 대화/영상 위에 물결을 얹지 않습니다. 실제 설치 앱과 모든 기기에서 시안과 픽셀 단위로 같다고 주장하지 않습니다.

## 같은 화면 크기의 비교

`test/liquid-glass.browser.cjs`는 같은 합성 데이터/브라우저/크기에서 기준 CSS와 현재 CSS만 교체합니다. 모든 주요 컨테이너/버튼의 경계 좌표가 전후 동일함을 검사합니다.

- 웹 1440×900: 기본 화면, 양쪽 메뉴를 연 화면.
- Chrome 앱 배치 1440×900: standalone 미디어 조건 모의. 실제 OS 설치를 뜻하지 않음.
- 모바일 390×844: 기본 화면, 양쪽 메뉴.
- 좁은 화면 320×740, 가로 화면 844×390.
- 결과: `comparison.html`, 원본 PNG, `liquid-results.json`을 같은 디렉터리에 생성.
- CI 증거: PR #52 → 최신 Channel videos regression → channel-browser-screenshots → liquid-glass. `comparison.html`과 이미지를 함께 열면 슬라이더로 전후 비교 가능.
- 현재 환경: `/tmp/fromm-liquid-final-review/`.

## 성능·가독성 로컬 측정

120개 합성 메시지를 사용한 Chromium 헤드리스 스크롤 표본입니다. 각 조건/버전에서 3회 실행하고 중앙값을 비교했습니다. 다른 로컬 브라우저 검사와 동시에 측정하지 않았습니다. 물리 기기 GPU 또는 실제 방송의 영상 FPS 측정은 아닙니다.

| 상태 | 중앙 프레임 간격 전→후 | P95 프레임 간격 전→후 | JS heap 전→후 |
| --- | --- | --- | --- |
| 웹 기본 | 16.7→16.7ms | 16.8→16.7ms | 1.88→1.88MiB |
| 웹 양쪽 패널 | 16.7→16.7ms | 16.7→16.7ms | 2.96→2.96MiB |
| 고정형 앱 배치 | 16.7→16.7ms | 16.8→16.8ms | 2.24→2.27MiB |
| 모바일 기본 | 16.7→16.7ms | 16.8→16.8ms | 1.88→1.88MiB |
| 모바일 양쪽 패널 | 16.7→16.7ms | 16.8→16.8ms | 2.96→2.96MiB |

- 초기 고정 앱에서 33.3ms로 악화된 결과를 확인하고 수정했습니다. 고정/넓은 패널에는 큰 실시간 블러를 쓰지 않으며, 좁은 메뉴만 2px로 제한했습니다. 물결·유리 가장자리·반사광은 정적 재료로 유지합니다.
- 추가 이미지: WebP 1600×600, **61,810 bytes**, 문서당 장식 요청 1개. 반복 타이머/추가 Canvas/WebGL/움직이는 왜곡 없음. 서버 API 요청 추가 없음.
- 디코딩 픽셀 면은 RGBA 기준 약 3.66MiB로 추정합니다. JS heap 수치에는 이미지/GPU 메모리가 포함되지 않습니다. 전체 GPU 메모리는 실측하지 않았습니다.
- 전경 글자만 잠시 숨겨 실제 합성 배경 픽셀을 샘플링했습니다. 뒤쪽 대화는 유지하고 텍스트의 DOM Range를 사용해 닫기 아이콘/빈 패딩을 배경으로 오인하지 않게 했습니다. 선택된 가시 라벨의 최저 대비 **4.81:1**. 전체 서비스 접근성 인증은 아닙니다.
- 320px 안내문에서 발견한 3.96:1은 더 진한 글자색으로 수정했습니다. 기존 axe 및 패널·터치/키보드 회귀 검사도 별도로 유지합니다.

## 검증 범위와 남은 확인

- 생산 코드 변경은 `glowme.css`와 새 장식 WebP입니다. `index.html`, 기능 JS, Native/확장, manifest/SW/아이콘은 기준 커밋과 동일합니다.
- Node 277개 통과(로컬 실제 Agora 타입 포함). 최종 커밋의 원격 CI 상태는 PR 최신 Checks를 기준으로 확인합니다.
- 실제 앱 설치는 임시 프로필 CDP에서 시도했으나 제공 Chromium에 `PWA.install` 프로토콜이 없어 실행할 수 없었습니다. 검증 우회/설치 도구 변경은 하지 않았습니다.
- 실제 Chrome 설치·업데이트/OS 창, Fromm 인증 스트림·실방송·Native 연결, 물리 모바일/iOS/Safari는 미검증입니다.
- main 병합/공개 배포/새 PR/기능 추가/Native·확장 변경/Hooks 활성화 없음.


## 후속 로고 정리

위 Liquid Glass 비교는 2ba8916 기준의 기록입니다. 이후 사용자가 사이드바 로고의 사각 테두리를 제거하도록 요청해 해당 로고만 투명 PNG로 교체하고 CSS 프레임을 제거했습니다. 표시 크기/레이아웃과 PWA 앱 아이콘은 유지했습니다. 옛 로고가 캐시에 남지 않도록 SW 공개 아트워크 캐시 버전만 v2로 올렸으며 허용 목록/인증·미디어 캐시 정책은 그대로입니다. 로컬 PWA 4개 및 기존 Glow ME 브라우저 검사 통과. 최신 상태는 HANDOFF와 PR HEAD Checks를 확인하세요.
