# PC 투명 유리와 화면 설정

PC 기본 주소에서 헤더와 사이드바를 중성 투명 유리로 표시합니다.
페이지의 기존 민트 배경, 선택 강조색과 저장 버튼의 청록색은 유지합니다.
기존 `?headerGlass=regular` 주소도 사용할 수 있지만 플래그는 필요하지 않습니다.
모든 자료는 합성이며 실계정 대화/사진/방송이 아닙니다.

## 구현과 조작

사이드바 하단 톱니바퀴에서 화면 설정을 엽니다. 굴절, 두께, 흐림, 채도,
유리 밝기(중성 흰 tint), 광택을 함께 조절하며 자동 저장/복원/기본값 복원을 제공합니다.
스위치를 끄면 기존 민트 화면을 사용합니다. 저장은 장치의 `fromm.pcGlass.v1`에
허용된7개 값만 기록하며 인증/미디어 자료를 저장하지 않습니다.

기존 MIT vendor의 public LiquidGlass를 장식 면에 각각1개 사용합니다.
공개 update() API를160ms 주기로 호출하고 change에서 마지막 값을 즉시 반영합니다.
불투명 중앙 민트 face를 제거했으며 글자/버튼 부모에는 필터/변형을 적용하지 않습니다.
배경이 굴절되는 동안 실제 클릭 위치, 도구 줄/목록 높이와 스크롤 위치는 유지됩니다.
기존 저장 버튼의 짧은 첫 선택 효과도 보존합니다.

## 검증

1440/760/900 standalone 모의/짧은900×560 창에서 설정·실제 엔진 옵션·연속 드래그·
초기화·재진입/새로고침 복원·탭 간 동기화·선택/저장/X·영역 겹침·초점 복귀를 검사했습니다.
설정 dialog의 axe 위반은0개입니다. 잘못된 저장 값/저장 차단/늦은 vendor import와
접근성·미지원·저사양 대체도 확인했습니다. 로그인에서는 vendor를 받지 않고,
다운로드를 지연한 상태에서도 사이드바와 선택이 먼저 동작합니다.

메뉴가 스크롤되는 짧은 PC 창에서는 커서 캡슐 좌표에 메뉴 스크롤을 반영하고
스크롤 중 이전 hover를 지워 잔상을 방지합니다. 모바일390 대표 화면에서 PC
설정/재질이 나타나지 않고 선택/저장과 화면 폭이 유지됩니다. 기존 필수 검사도 수행합니다.

## 성능과 제한

기본값은 굴절34/두께28/흐림0/채도108/흰 밝기28%/광택0입니다.
흐림/광택을 높이면 더 많은 렌더링 작업이 필요합니다.
스크롤 중에는 실제 SVG와 맵이 유지됩니다. 사이드바 너비 전환만 기본 유리로
잠시 표시하고, 영상 재생 중에는 SVG/배경 blur를 해제한 흰 투명 오버레이를 사용합니다.
접근성 설정, 저사양/미지원/실패 및 면적 예산에 맞는 대체 표시를 유지합니다.

단독 실행한3쌍 표본의 중앙값([최종 원시](performance.json), 각 약1.2초):

| 장면 | 유리 끔 → 켬 |
|---|---|
| 일반 스크롤 frame p95 | 16.8 → 16.8ms |
| 사이드바를 펼쳐 고정한 본문 스크롤 frame p95 | 16.8 → 33.4ms |
| 영상+메뉴 조작 frame p95 | 16.7 → 16.7ms |
| 영상 dropped / frames | 0 / 89 → 0 / 87 |
| 일반 스크롤 JS heap | 2.327 → 2.359MiB |

펼친 사이드바에서는 여전히 비용이 있습니다. GPU 사용률/총 GPU 메모리를 측정한
결과가 아니며 실제 기기 FPS 보장이 아닙니다. [blur2 전체 SVG](performance-blur2.json),
[blur 외부 합성 시제품](performance-native-blur-prototype.json),
[분할 렌더 시제품](performance-rim-prototype.json)도 비교했습니다.
추가 변환의 개선이 일정하지 않아 시제품 코드는 제외하고 공개 SDK를 직접 재사용했습니다.

실제 Windows/macOS 설치형PWA, Safari/Firefox 실기, 실계정 방송, 물리 GPU는 미확인입니다.
standalone/UA는 Chromium 모의입니다. 최종 CI/병합/배포/공개 URL 확인은 PR 완료 기록에 남깁니다.
