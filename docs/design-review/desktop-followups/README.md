## 저장 동작 보존

기존 `showDirectoryPicker`, 계정별 기본 폴더와 IDB 저장소를 유지했다. 기존 기본 키는 그대로 두고 아티스트별 키만 추가했다. 실제 쓰기, 확장자, 파일명, 변환, 중복 비교, `close()` 완료 확인, 실패·취소 처리와 결과 패널은 기존 함수가 담당한다. 변경한 것은 설정과 목적지 핸들 연결 계층이다.

일반 미디어는 현재 구독 아티스트의 폴더를 사용한다. Channel Artist는 실제 게시물 작성자를 구독 아티스트에 유일하게 연결할 수 있을 때 해당 폴더를 사용한다. 여러 멤버를 묶어 저장할 때도 게시물마다 미리 확정한 핸들을 사용한다. 알 수 없거나 중복된 이름, 일반 Channel·Replay 게시물은 기본 폴더를 사용한다. 저장 중 설정을 바꿔도 진행 중인 배치의 핸들은 바뀌지 않는다.

사진·영상은 선택한 루트에, 음성은 기존 **소문자 `audio/`**에 저장한다. `Audio/`로 바꾸지 않았다. 대소문자 이력은 이전 보고서에 설명돼 있다. 중복 파일은 기존 비교 기준으로 건너뛰며 권한 거부 뒤 다른 다운로드 방식으로 우회하지 않는다.

공개 명부는 현재 fromis_9와 OH MY GIRL을 지원한다. 새 그룹·알 수 없는 작성자는 기존 수신 게시물에서 유지하며 생년월일을 추측하지 않는다. 새 그룹 전체 명부는 별도 메타데이터 추가가 필요하다. 생년월일 출처: [fromis_9 공식 프로필](https://fromis9.fanpla.jp/news/2/?lang=en), [Sony 공식 OH MY GIRL 프로필](https://www.sonymusic.co.jp/artist/ohmygirl/profile/). 후자는 오래된 소개 문구가 있어 날짜 확인용으로 사용했으며 현 멤버 명단은 현재 공개 명단과 대조했다.

## 사진 갱신·읽기 위치 밀림 수정

처음에는 해결책만 보고하는 범위였지만, 사용자가 이후 수정까지 요청해 같은 PR에 구현했다.

원인은 가상 창/전체 렌더 때 이미지까지 다시 생성하고, 사진의 로딩 전 크기를 예약하지 않으며, 이전 메시지 삽입 시 위치 보정을 한 번만 수행하던 구조였다. `content-visibility:auto`의 추정 높이도 사진이 늦게 크기를 얻을 때 바뀐다. DOM 교체가 항상 네트워크 재다운로드를 뜻하지는 않지만, 복구된 Blob 상태를 잃거나 디코딩을 반복하는 경로가 있었다.

- 같은 계정·대화방·메시지 내용의 겹치는 사진 행은 동일한 이미지 노드와 복구 상태를 재사용한다. 한 번의 동기 렌더에서만 재사용 풀을 유지하고, 별도 창의 메시지 DOM을 계속 쌓지 않는다. 사진 주소/인용 내용/검색 표시 등이 바뀌면 새로 렌더한다.
- 명시된 크기 메타데이터 또는 성공적으로 로드한 사진의 실제 크기로 종횡비와 공간을 확보한다. 기존 최대 높이 560px과 가로 반응형 크기, 세로 사진의 비율을 유지한다. 확인된 크기와 정상 HTTP 주소는 최근 512개까지만 메모리에 보관하며 계정·본인 식별자·대화방을 구분한다. 메시지나 이미지 바이트를 새로 영구 저장하지 않는다.
- 새 사진이 포함되거나 아직 로딩 중인 사진이 있는 구간을 삽입할 때 화면 안의 실제 읽기 앵커를 선택하고, 늦은 이미지/폰트/높이 변화까지 한 번에 최대 12초간 보정한다. 백그라운드 렌더가 발생해도 읽기 앵커를 새 DOM에 전달한다. 휠·키보드·포인터 입력, 탭·방·계정 변경과 화면 숨김이 우선하며, 모바일/좁은 화면에서는 기존 동작을 유지한다.
- 화면에서 제거된 사진의 Blob URL을 해제하고, 제거 뒤 늦게 끝난 복구 요청은 새 Blob URL을 만들지 않는다. 기존 CDN → 원본 → Blob 복구 순서, 갤러리·원본 미리보기와 파일 저장 함수는 유지한다.

동일한 합성 지연 사진 20장을 이전 창 위에 삽입해, 삽입 직후와 로딩 후 같은 메시지의 화면 Y 좌표를 비교했다. 지연 크기 변화만 분리하기 위해 새 사진은 eager로 요청했다. 기준 코드는 수정 전 PR head `fed9110`이며 새 코드와 같은 데이터·화면 크기·브라우저 설정을 사용했다.

## 검증 및 한계

Node 24.22.3 / Playwright 1.62.1 / Chromium 151.0.7922.34. 웹 및 Native 단위 테스트 337 통과, 기존 Agora 1건 건너뜀.

로컬 브라우저 통과: 지연 사진/노드 재사용/세로 비율/Blob 복구·해제/수동 취소/화면 크기 전환/계정 초기화, 캐시 복원·새로고침·원문/내 답장 탐색·5만 건 대화, 새 멤버·체크박스·최신 이동 테스트, 아티스트 폴더 설정과 실제 OPFS 저장, 기존 기본 폴더 재사용, 미디어 일괄 저장, 저장 상태 UI, 직접 선택, Channel 사진·영상, 대화 상태·입력 컨트롤, 로그인 초기 화면, 초기 탐색 소유권, 프로필 병렬 조회, 설정·테마, 기존 맨 위 이동. 기본/어두운 테마와 모바일 회귀는 기존 관련 스위트에서 포함한다.

새 테스트는 최초 게시물 없는 명부, 영문 별칭, 3,000개 대화에서의 제한된 DOM, 실제 여러 스크롤 좌표, 중단과 동작 감소를 확인한다. 폴더 테스트는 계정 분리, IDB 재로드, 기본 대체, 서로 다른 멤버가 섞인 배치, 중복, 권한 거부, 기본 복원 후 기존 파일 보존을 확인한다. 사진·영상·음성 파일의 아티스트 폴더 경로도 검사한다.

5만 건 합성 캐시 복원은 화면 DOM 241개와 과거 이력 재조회 0건을 유지했고, 별도 5만 건 초기 수집에서도 최신 내용이 먼저 표시된 뒤 전체 기록이 완성됐다. 파일 시스템 저장 로직과 기존 대화 IDB의 완전성·충돌 처리에는 변경이 없다.

합성 지연 환경에서 프로필 요청이 방 목록 요청과 같은 시각에 시작했고 두 요청을 동시에 보류해도 인증 게이트는 유지됐다. 실제 첫 진입 전체 속도의 전후 수치나 실제 서비스 API 지연은 측정하지 않았다. 신규 계정의 로그인 자체, 네트워크/확장프로그램 지연 및 최초 대화 수집 시간까지 제거하는 변경은 아니다.

실제 사용자 폴더, OS 네이티브 권한 창, 실제 서비스 미디어·계정, 물리 기기와 Safari는 미검증이다. 브라우저 파일 시스템 API가 없는 환경은 기존 기능 범위를 유지한다. 공개 명부 갱신은 현재 수동이며 서버의 새로운 멤버 데이터 API를 추측해서 추가하지 않았다. CI·병합·배포 결과는 PR과 CODEX_HANDOFF.md의 최종 기록을 확인한다.
