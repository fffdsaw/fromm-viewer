## 총평과 제품 고유성

현재 화면은 아티스트의 대화와 미디어를 오래 읽고 보관하는 개인 아카이브라는 성격을 갖는다. 프로필·아티스트별 통계·대화 말풍선·미디어 분류가 제품 맥락을 만든다. 범용 관리 대시보드에 색만 바꾼 결과는 아니다. 민트 배경과 어두운 재생 영역의 역할도 구별된다.

가장 큰 남은 문제는 색이나 장식보다 **검색 중 다음 행동의 접근성, 그리고 기록 수집이 중단되었다는 사실의 가시성**이다. 정상 상태의 조용함을 유지하면서 이 두 상태만 더 명확하게 만들면 된다.

## 잘된 점

1. **확장 레일이 공간을 덜 차지하면서 본문 위치를 유지한다.** 다섯 context에서 Enter로 펼치고 Escape로 접을 수 있었고, 초점은 `#sidebarToggleBtn`으로 돌아왔다. 펼치기 전후 `#timeline` 좌표가 유지됐다. 844×390의 확장 메뉴는 3×3 배열로 9개 목적지를 유지하며 아티스트 목록에 별도 스크롤 영역을 남긴다. 승인된 구조를 바꿀 이유가 없다.
2. **읽기와 작업 도구의 우선순위가 명확하다.** 프로필/아티스트/통계가 하나의 헤더로 모이고, 검색은 전체 대화에서만 나타나며, 선택 이후에만 배치 도구가 뜬다. 실제 카드 클릭으로 선택 상태와 떠오르는 도구를 확인했다. 모든 검사 화면에서 가로 넘침은 없었다.
3. **영상 표면을 보호했다.** Channel과 Replay를 실제 로컬 MP4로 열어 320/390/844/1440/PWA에서 디코딩·재생·정지 및 목록 복귀를 확인했다. 어두운 재생 영역과 흰색 조작부가 유지되고 화면 하단을 넘지 않았다. 844×390 영상 rect는 y=148.23~377, 320×640 Channel은 y=236.59~631이었다. 이는 레이아웃·로컬 영상 검증이며 실제 LIVE/Agora나 HLS 전송 성공을 뜻하지 않는다.

## 우선 문제

### P1 — 고정 검색 패널이 검색 결과 이동 버튼을 가린다

- **위치:** `.toolbar #chatMatchNav`, `#chatMatchNext`, `#chatToolsPanel`, `.viewer-header`의 stacking context.
- **재현:** 1440×900 PWA emulation에서 `합성 대화 17`을 검색하면 8개 결과가 나온다. 다음 버튼은 x=1313, y=841, 32×34px인데, 중심점 hit-test가 `#chatToolsPanel`을 반환한다. 실제 Playwright 클릭도 `chatToolsPanel intercepts pointer events`로 실패했다. PWA에서는 패널 닫기 버튼이 숨겨져 있다.
- **추가 범위:** 844×390 일반 브라우저에서도 열린 패널의 `#chatContextBtn`이 다음 버튼(x=727, y=331)을 가리고 클릭을 가로챘다. 일반 브라우저는 패널을 닫으면 우회 가능하다. 320px에서는 같은 버튼 클릭이 정상 작동해 검색 자체의 오류가 아닌 배치 문제임을 확인했다.
- **영향:** 검색 결과 이동이라는 주요 보조 동작이 PWA에서 보이지도, 포인터로 실행되지도 않는다.
- **수정:** 패널이 열려 있거나 고정된 경우 이전/다음/위치를 검색 결과 수 옆의 패널 내부 행으로 배치한다. 패널이 닫힐 때만 기존 떠 있는 이동 도구를 노출한다. 단순 z-index 증가는 다른 날짜·검색 버튼을 덮을 수 있다.
- **증거:** `followup.json`, `1440x900-pwa-match-nav-hit.png`, `844x390-match-nav-hit.png`, `1440x900-pwa-search-results.png`.
- **추천 명령:** `$impeccable harden`, `$impeccable layout`.

### P1 — 기록 준비 중단 상태와 재시도 안내가 화면에서 사라진다

- **위치:** `glowme.css`의 `.glowme-phase3 #scanState`, `web-glowme.js`의 `syncHeader()`, `index.html`의 `updateHistoryStatus()`.
- **재현:** 이미 180개를 불러온 상태에서 `state.hasMoreMessages=true`, `state.historyError`를 설정하고 실제 상태 갱신 함수를 호출했다. `#scanState`의 내용은 `180개 · 기록 준비 일시 중지 · 새로고침으로 재시도`로 정확하지만 `clip-path:inset(50%)`이고, 844×390에서는 `display:none`까지 적용된다. 화면에는 `현재 미디어 71 · …`만 보인다. 오류 설명은 통계 요소의 `title`에만 존재한다.
- **영향:** 사용자는 목록이 더 있는지, 수집이 계속되는지, 멈췄는지 구별하기 어렵다. 모바일에서는 title을 안정적으로 확인할 방법도 없다. 검색·전체선택·보관 작업을 완전한 기록으로 오인할 수 있다.
- **수정:** 평상시 헤더의 간결함은 유지하되 오류 발생 시에만 `기록 불러오기가 멈췄어요 · 다시 시도`를 보이는 상태 행과 실제 재시도 동작으로 제공한다. 진행 중·부분 집계·완료도 읽을 수 있는 짧은 표현으로 구별한다.
- **증거:** `interactions.json`의 `errorPresentation`, `320x640-history-error.png`, `1440x900-history-error.png`. 합성 오류 상태 재현이며 실제 API 장애 발생을 주장하지 않는다.
- **추천 명령:** `$impeccable clarify`, `$impeccable harden`.

### P2 — 가로 화면에서 날짜 선택을 눌러도 달력이 보이지 않는다

- **위치:** `#datePickerBtn`, `#dateCalendar`, `#chatToolsPanel`, `openDateCalendar()`.
- **재현:** 844×390에서 날짜 선택 클릭 후 달력은 열린 상태이지만 panel bottom=378px, calendar top=387.34px, 첫 날짜 top=464.34px이다. 스크린샷에는 날짜 선택 버튼까지만 보이며 월/날짜는 모두 패널 바깥의 스크롤 영역 아래에 있다.
- **영향:** 누른 반응이 광택 변화뿐이라 달력이 열리지 않았다고 생각하기 쉽다. 패널 안을 직접 스크롤하면 사용할 수 있어 P2로 분류했다.
- **수정:** 달력을 열 때 패널 자체의 스크롤을 조정해 월 선택과 날짜 행을 즉시 보이게 한다. 키보드 초점도 선택일 또는 첫 유효 날짜로 연결한다. 본문 스크롤은 이동시키지 않는다.

### P2 — 축소 레일에서 두 쌍의 목적지가 같은 아이콘이다

- **위치:** `web-glowme.js`의 `paths.media` / `paths.image`, `paths.video` / `paths.live`.
- **관찰:** 미디어와 사진은 같은 그림 아이콘, 영상과 LIVE는 같은 비디오 카메라 아이콘이다. 320/390/1440의 축소 상태에서 각각 같은 모양이 반복된다. 레일을 펼치면 이름을 확인할 수 있으므로 우회는 가능하다.
- **영향:** 축소 레일을 익힌 사용자도 목적지의 위치를 기억해야 하고, 터치 사용자는 구별을 위해 추가로 펼쳐야 한다.

- **증거:** `320x640-chat.png`, `1440x900-chat.png` 및 위 `paths` 정의.
- **추천 명령:** `$impeccable clarify`, `$impeccable polish`.

## 인지 부하

- 단일 초점, 정보 그룹 관계, 시각적 위계, 작업 맥락 유지, 필요 시 도구 노출은 대체로 통과한다.
- 체크리스트에서 **chunking(≤4)**과 **minimal choices(≤4)**는 확장된 9개 탐색 항목 때문에 엄격하게 세면 실패한다. **2/8 실패, moderate**. 이는 사용자 승인 요구이므로 메뉴 수를 줄이라는 뜻이 아니다. 선택된 항목 강조와 서로 다른 아이콘으로 식별 비용을 낮추는 것이 맞다.
- 9개 탐색 목적지와 긴 아티스트 목록은 한 번에 4개를 넘는 결정 지점이다. 다만 아티스트 구분선/제목과 독립 스크롤이 이미 분리되어 있다.
- 검색 패널에서는 내 답장, 검색, 문맥 보기, 날짜, 이동이 함께 있으나 작업별 레이블로 묶인다. 가로 화면에서 달력이 보이지 않는 순간에는 사용자가 패널의 내부 스크롤 구조까지 추론해야 한다.
- 사진 카드의 단일 클릭=선택, 더블클릭=미리보기 규칙은 코드와 실제 선택 동작으로 확인했다. `.selection-toggle`은 초점 전에는 시각적으로 숨겨져 있다. 최초 진입 시 짧은 안내나 보이는 선택 진입점이 있으면 학습 비용을 줄일 수 있다. 기존 제스처를 바꾸라는 제안은 아니다.

## 감정 흐름

첫 진입은 부드럽고 조용하다. 선택한 아티스트의 얼굴과 대화가 중심이라 정서적 목적에 맞는다. 레일의 확장과 읽는 위치 유지도 안정감을 준다. 검색 하이라이트는 찾았다는 작은 성공을 만든다.

감정적 저점은 그 다음이다. PWA에서 검색 결과 이동이 가려지고, 네트워크 중단 상태는 겉으로 정상 목록처럼 보인다. 이 두 순간을 명료하게 처리해야 차분함이 답답함으로 바뀌지 않는다. 저장 결과와 실패 항목 재시도 UI는 소스에 존재하지만 실제 파일 저장의 종료 경험은 이번 평가에서 실행하지 않았다.

## 관련 사용자 관점

- **모바일 팬/첫 사용자:** 축소 레일에서 미디어·사진, 영상·LIVE를 구별하기 위해 펼침이 필요하다. 가로 방향에서는 날짜 버튼을 눌러도 날짜가 나타나지 않아 다시 누를 수 있다.
- **대량 보관 사용자:** 부분 수집 중단을 명확히 알 수 없다. PWA의 검색 이동 버튼이 가려져 다수 검색 결과를 순회하기 어렵다. 배치 도구와 보기별 위치 보존은 이 사용자에게 적합하다.
- **키보드·저시력 사용자:** 레일 열기/닫기/초점 복귀는 확인됐다. 색만으로 선택을 표시하지 않는 accessible state도 있다. 그러나 숨겨진 기록 오류와 메뉴의 동일 실루엣은 시각적 상태 파악을 어렵게 한다. 실제 스크린리더 발화 검사는 수행하지 않았다.

## 작은 관찰 / 별도 시각 마감

- 날짜 선택 활성 상태와 일부 선택/정렬 버튼에 이전의 밝은 시안 광택이 남아 있다. 현재의 연두·민트보다 강조가 강하다. Meapri 시험 적용 이후 별도 마감에서 이 상태들을 함께 조율하면 된다. 이를 현재 단계의 출시 차단 결함으로 세지 않았다.
- 320px 플레이어 제목은 뒤로/다운로드 버튼 사이에서 짧게 잘린다. 재생 컨트롤과 영역을 보호하면서 전체 제목을 확인할 수 있는 보조 방법을 검토할 수 있다. 플레이어 동작 변경을 권하지 않는다.
- 검색 필드의 브라우저 기본 clear와 별도 clear가 동시에 보인다. 작은 중복이므로 기능 문제보다 뒤의 마감 순서에 둔다.
- 확대 레일/검색 패널을 통해 뒤의 글자가 희미하게 비친다. 최종 비주얼 단계에서 읽기 간섭이 없는 정도의 불투명도를 정하면 된다.

## 검증 한계와 정리

- HTTP fixture 서버 3개는 각 스크립트의 `finally`에서 닫혔다. 브라우저도 닫았다. 서버 종료는 `measurements.json`, `interactions.json`, `followup.json`의 `serverStopped:true`로 기록됐다.
- fixture는 원격 프로필/API/영상 응답을 합성한다. 실제 로그인, 계정·CDN 지연, Agora LIVE, HLS 전송, 저장 권한/완료, 실물 모바일 브라우저, OS 설치형 PWA, 스크린리더는 검증하지 않았다.
- PWA 검사는 display-mode emulation이다. 실제 설치 성공을 의미하지 않는다.
- `interactions.json`의 다섯 context에는 pageerror가 없었다. `followup.cjs`는 마지막 320px 검색 이동이 성공하며 패널이 닫힌 뒤, 닫힌 검색 지우기 버튼을 다시 누르려 해서 끝에서 timeout이 났다. 이는 검사 스크립트의 후속 단계 문제로 기록하며 제품 결함으로 세지 않았다. 앞선 PWA/844px hit-test와 클릭 차단 증거, 달력, 실제 선택 증거는 저장됐다.
- `measurements.json`의 `active` 필드는 `[aria-current]` 속성 존재만 조회한 초기 수집 실수 때문에 항상 all로 기록됐다. 해당 필드를 탐색 오류의 증거로 사용하지 않았다. 이후 `interactions.json`은 `[aria-current="page"]`로 바로잡았으며 실제 UI 클릭 경로를 사용했다.
